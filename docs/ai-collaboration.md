# AI 협업 기록

## 사용 원칙

- AI는 요구사항 분해, 코드 초안, 테스트 후보와 문서 정리에 활용한다.
- 생성된 코드는 실행 및 테스트하고, 설명할 수 있는 코드만 반영한다.
- 금액과 중복 여부처럼 동일한 입력에 같은 결과가 필요한 판단은 Java 코드로 구현한다.
- AI는 검수 결과 설명과 확인 사항 제안에만 사용한다.
- AI의 제안은 사용자 승인 전까지 실제 처리 상태를 변경하지 않는다.

## 초기 설계에서 직접 결정한 내용

1. AI API 키가 없어도 검수 기능을 실행할 수 있도록 `AiReviewExplainer` 인터페이스를 분리했다.
2. AI 연결 실패 시 규칙 기반 결과가 사라지지 않도록 기본 설명 구현을 먼저 만들었다.
3. 검수 규칙을 각각 독립된 클래스로 구성해 규칙을 추가하거나 테스트하기 쉽게 했다.

## 구현 협업 기록

- CSV 오류 조건과 구조화된 AI 응답 형태를 정리하고 구현 초안을 생성했다.
- 생성 코드는 단위 테스트와 실제 HTTP 호출로 검토하며 규칙 판정과 AI 설명의 경계를 유지했다.
- 별도 React 프로젝트와 DB 저장은 핵심 흐름에 필요하지 않아 제외하고 단일 정적 화면을 사용했다.
- macOS 최초 실행에서 `gradlew` 실행 권한과 CRLF 줄바꿈 문제를 확인해 수정했다.
- AI가 정상 여부를 판정하는 방식은 채택하지 않았다. 판정은 항상 Java 규칙 결과만 사용한다.
- MockMvc 통합 테스트로 CSV 업로드와 사용자 결정 저장·조회를 검증했다.
- 실제 브라우저에서 샘플 CSV 업로드, AI 설명 표시, 정상 처리 버튼과 반응형 화면을 직접 확인했다.
- 운영 저장소는 MySQL로 전환하고, 통합 테스트만 H2 MySQL 호환 모드로 빠르게 실행하도록 분리했다.
