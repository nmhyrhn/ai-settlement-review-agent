# AI 협업 기록

## 사용 원칙

- AI는 요구사항 분해, 코드 초안, 테스트 후보와 문서 정리에 활용한다.
- 생성된 코드는 실행 및 테스트하고, 설명할 수 있는 코드만 반영한다.
- 금액과 중복 여부처럼 동일한 입력에 같은 결과가 필요한 판단은 Java 코드로 구현한다.
- AI는 검수 결과 설명과 확인 사항 제안에만 사용한다.
- AI의 제안은 사용자 승인 전까지 실제 처리 상태를 변경하지 않는다.

## 초기 설계에서 직접 결정한 내용

1. AI API 키가 없어도 검수 기능을 실행할 수 있도록 `AiReviewExplainer` 인터페이스를 분리했다.
2. AI 연결 실패 시 규칙 기반 결과가 사라지지 않도록 기본 설명 구현을 먼저 만들었다.
3. 검수 규칙을 각각 독립된 클래스로 구성해 규칙을 추가하거나 테스트하기 쉽게 했다.
4. 금액·중복·증빙 여부는 같은 입력에 항상 같은 결과가 나와야 하므로 AI가 아닌 Java 규칙으로 판정했다.
5. AI에는 전체 CSV가 아니라 Java가 판정한 거래와 위반 결과만 전달해 입력 범위와 비용을 줄였다.
6. AI 응답은 자유로운 문장이 아니라 `summary`, `checkPoints`, `suggestedAction`, `available` 구조로 제한했다.
7. AI가 제안한 `APPROVE`, `RECHECK`, `HOLD`는 화면에 표시만 하고 사용자가 버튼을 누른 경우에만 별도 이력으로 저장했다.
8. CSV의 필수 헤더와 순서를 고정하고 빈 파일, 날짜·금액 형식, 0원 이하 금액, 거래 ID 중복을 서버에서 검증했다.
9. 운영 이력은 MySQL에 저장하되 테스트에서는 H2의 MySQL 호환 모드를 사용해 테스트 속도와 재현성을 확보했다.
10. 거래 원문 전체를 저장하지 않고 사용자 결정 이력만 저장해 현재 MVP의 데이터 범위를 작게 유지했다.
11. 별도 React 프로젝트 대신 Spring Boot 정적 리소스 한 페이지를 선택해 배포 단위와 실행 절차를 하나로 유지했다.
12. API 키와 DB 접속 정보는 코드에 넣지 않고 `.env`와 환경변수로 분리했다.

## AI 결과를 그대로 사용하지 않고 검토한 내용

- AI가 거래의 정상 여부까지 판정하는 구조는 결과 재현성이 떨어져 채택하지 않았다.
- AI 오류를 전체 API의 `500` 응답으로 처리하는 방식은 규칙 검수 결과까지 잃게 되므로 fallback 응답으로 변경했다.
- 별도 프론트엔드 프로젝트는 화면 규모에 비해 설정과 배포가 늘어나므로 채택하지 않았다.
- 승인 이력 구현에 JPA 엔티티와 Repository 계층을 추가하는 방식은 단일 테이블 MVP에 과하다고 판단해 JDBC로 단순화했다.
- 로컬 이력을 H2 파일에 저장하는 초기 방식은 실제 제출 환경을 고려해 MySQL로 변경했다.
- AI가 생성한 코드는 단위 테스트, MockMvc 통합 테스트, curl 호출, 실제 브라우저 조작 순서로 확인했다.

## 구현 중 발견하고 수정한 문제

- Windows 줄바꿈으로 `gradlew`가 macOS에서 실행되지 않아 LF 줄바꿈과 실행 권한을 수정했다.
- 이전 서버가 8080 포트를 점유해 `bootRun`이 실패한 문제를 빌드 실패와 분리해 확인했다.
- `.env`가 Spring Boot에서 자동으로 로드되지 않아 `spring.config.import`를 추가했다.
- H2 파일 DB에서 `schema.sql`이 자동 실행되지 않는 문제를 실제 API 호출로 발견해 SQL 초기화 설정을 보완했다.
- MySQL 전환 후 H2 테스트에 MySQL 호환 모드를 적용해 동일 스키마를 검증했다.
- 브라우저 검수에서 설명 라벨의 간격 문제를 발견해 CSS 선택자와 줄바꿈을 수정했다.

## 구현 협업 기록

- CSV 오류 조건과 구조화된 AI 응답 형태를 정리하고 구현 초안을 생성했다.
- 생성 코드는 단위 테스트와 실제 HTTP 호출로 검토하며 규칙 판정과 AI 설명의 경계를 유지했다.
- 별도 React 프로젝트는 핵심 흐름에 필요하지 않아 제외하고 단일 정적 화면을 사용했다.
- macOS 최초 실행에서 `gradlew` 실행 권한과 CRLF 줄바꿈 문제를 확인해 수정했다.
- AI가 정상 여부를 판정하는 방식은 채택하지 않았다. 판정은 항상 Java 규칙 결과만 사용한다.
- MockMvc 통합 테스트로 CSV 업로드와 사용자 결정 저장·조회를 검증했다.
- 실제 브라우저에서 샘플 CSV 업로드, AI 설명 표시, 정상 처리 버튼과 반응형 화면을 직접 확인했다.
- 운영 저장소는 MySQL로 전환하고, 통합 테스트만 H2 MySQL 호환 모드로 빠르게 실행하도록 분리했다.
