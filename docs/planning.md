# AI 정산 검수 Agent 기획

## 문제

정산 담당자는 중복 결제, 기준 금액 초과, 증빙 누락을 반복해서 확인한다. 검수 결과가 담당자의 판단에만 남으면 확인 이유와 후속 처리가 일관되게 기록되지 않을 수 있다.

## MVP 목표

정확한 조건 판별은 Java 코드로 수행하고, AI는 검수 결과의 설명과 확인 사항 제안에만 사용한다. AI가 제안한 작업은 사용자의 승인 없이 실행하지 않는다.

## 사용자 흐름

1. 정산 CSV를 업로드한다.
2. 서버가 CSV를 거래 목록으로 변환하고 검수 규칙을 실행한다.
3. AI가 이상 항목의 원인과 확인 사항을 설명한다.
4. 사용자가 정상 처리, 재확인 또는 보류를 선택한다.
5. 사용자가 선택한 결정을 이력으로 저장한다.

## 검수 규칙

| 규칙 | 조건 | 코드 |
|---|---|---|
| 중복 결제 | 날짜·거래처·금액이 동일한 거래가 2건 이상 | `DUPLICATE_PAYMENT` |
| 기준 금액 초과 | 결제 금액이 1,000,000원 초과 | `AMOUNT_EXCEEDED` |
| 증빙 누락 | 증빙 번호가 비어 있음 | `RECEIPT_MISSING` |

## 역할 구분

| 처리 | 담당 |
|---|---|
| 금액·중복·증빙 판별 | Java 검수 규칙 |
| 검수 결과 설명 | AI |
| 최종 처리 상태 결정 | 사용자 |
| 검수·승인 이력 저장 | Spring Boot |

## 구현 순서

- [x] Spring Boot 프로젝트와 검수 도메인 구성
- [x] 검수 규칙 3개 및 단위 테스트
- [x] JSON 기반 검수 API
- [x] CSV 업로드 및 파싱
- [x] OpenAI 구조화 설명 생성과 실패 fallback
- [x] 승인·보류 상태와 실행 이력 영구 저장(MySQL)
- [x] 검수 결과 화면
- [x] API 통합 테스트와 실행 화면 정리
